# Engineering and security audit

This document records the November 2026 review of the `audit/secure-transport-ci-docs-2026-11` change set. It describes code-reviewed improvements rather than implying a formal third-party security certification.

## Findings and remediation

| Finding | Priority | Outcome |
| --- | --- | --- |
| Authenticated GET cache shared across Mastodon accounts | High | Cache partitioned by SHA-256 digest of the access token; requests with custom Authorization headers bypass caching |
| Request retries could deadlock serial request queue | High | Retries run after the queued request settles |
| Retrying writes could duplicate posts or admin changes | High | Automatic retry is restricted to read-only HTTP methods |
| Absolute API endpoints, URI overrides or redirects could expose bearer credentials | High | Enforce credential-origin match, reject URL/redirect overrides, disable redirect following |
| Query strings and response payloads could leak through diagnostic error logging | Medium | Log endpoint paths rather than query strings; omit response bodies and stacks from transport diagnostics |
| Mixed missing/ISO rate-limit headers could corrupt queue state | Medium | Validate headers; parse ISO-8601 or numeric reset timestamps |
| Failure handling silently dropped remaining workflow items | Medium | Emit an error per item and continue processing where `continueOnFail` is enabled |
| PKCE generated by an outdated direct runtime dependency | Medium | Use Node.js CSPRNG and SHA-256 (RFC 7636 S256); remove the direct dependency |
| Two lockfiles represented different package managers | Medium | Use pnpm as the sole lockfile source of truth; remove the npm lockfile |
| End-of-life Node 20 included in supported runtime | Medium | CI and declared engine target supported Node.js LTS versions |
| Missing security disclosure / contributor templates | Low | Document reporting, support, audit scope, and review requirements |

## Dependency and CI policy

pnpm 10 is the canonical package manager. The CI pipeline must pass frozen-lockfile installation, ESLint, Jest and the production build on the supported Node.js versions. Dependabot monitors compatible dependency changes. Security-related dependency changes require a full transitive lockfile review, advisory triage, and CI verification; major n8n/Jest/ESLint/pnpm migrations are separate changes.

The old `pkce-challenge@2.2.0` **direct dependency was removed**, not silently replaced with a major release. Its security-critical functionality now uses Node.js built-in cryptographic APIs. Transitive packages are still pulled by development tooling and must be assessed in their own context.

## Remaining risks and follow-up work

1. The process-wide request queue and rate-limit accounting still need per-instance/per-account partitioning; one account can delay another.
2. Authentication callbacks and credential-preauthentication behavior need contract tests against a disposable Mastodon instance.
3. Cache TTL can produce stale GET results following mutations; consider explicit scoped invalidation.
4. The large operation routing switch should eventually become a typed registry with operation contract tests.
5. Review deployment policies for HTTPS-only production credentials, private-vulnerability reporting, branch protection, code-scanning and signed releases. Repository settings require administrator configuration.
6. Current tests are largely mocked unit tests; **no live Mastodon end-to-end test or external penetration test** is asserted.

Owners should review this report after major changes and keep release notes, security docs and the support matrix aligned.
